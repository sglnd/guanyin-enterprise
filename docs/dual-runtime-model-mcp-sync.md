# 空间版本选择与模型、MCP 同步

新建空间的默认选项为 `0.2.1-rc3`，备用选项为 `0.1.5-rc2`。
界面展示上游版本，内部版本 ID 和镜像地址继续区分企业修订。
空间创建时记录镜像，之后目录默认值改变不会替换已有空间镜像。

## 同步契约

平台对两个版本使用同一组受内部 Token 保护的接口：

- 模型：`/__guanyin/models/sync`，同步供应商、模型、默认模型和凭据。
- MCP：`/__guanyin/mcp-manager/list`、`add`、`remove`。
- 平台按空间串行更新；校验实际配置匹配后才标记同步完成。
- MCP 比较器兼容 0.1.5 的平铺配置与 0.2.1 的嵌套配置。

## 0.1.5 无 Key 兼容修正

隔离验证发现：旧 ARM 镜像虽接受无 Key 模型配置，SDK 调用仍以
`No API key for provider` 失败。新增 `patch-pi-no-auth.mjs`，对平台管理的
OpenAI Completions / Responses 路由省略 Authorization；已有 Key 优先使用。
补丁带精确匹配检查，重复运行不会再次修改。第三方供应商的凭据校验保持原行为。

修正镜像：`guanyin-enterprise-dsh:gy.ent.8-sync1-arm64`。
本地 Registry 摘要：`sha256:d139c31ed472a77a81c4e1c50728f084e91d9f8ab3387cec5b81dc3486e6229f`。
旧镜像和已有空间保留；新建 0.1.5 空间使用修正后的镜像。

## 可重复验证

`deploy/dsh-0.2.1/dual-runtime-sync-fixture.mjs` 提供合成模型与 MCP，
`dual-runtime-sync-check.mjs` 验证两个版本；可传 `015` 或 `021` 单独运行。
仅在无数据挂载的一次性测试容器运行，使用合成 Key，不调用客户模型。
fixture 监听 19094，测试容器映射 19095 / 19096 到 3080；容器需设置
`DSH_EXT_TOKEN=guanyin-dual-sync-proof-only` 和对应 `DSH_TRUSTED_HOSTS`。

覆盖模型同步、默认模型切换、供应商更新与移除，以及 MCP 同步、更新、工具发现、
实际工具执行、移除。无 Key 请求必须无 Authorization，带 Key 请求必须匹配合成 Key。
首次冷启动最多等待 240 秒；独立测试不修改真实空间。

## 本地验证结果（2026-10-27）

| 项目 | 0.1.5-rc2 企业修正镜像 | 0.2.1-rc3 企业 ent7 |
| --- | --- | --- |
| 无 Key 模型实际请求无 Authorization | 通过 | 通过 |
| 带 Key 模型实际请求使用同步凭据 | 通过 | 通过 |
| 默认模型切换、模型更新与移除 | 通过 | 通过 |
| MCP 新增、配置更新、移除 | 通过 | 通过 |
| 模型实际执行 MCP 工具 | 2 次 | 2 次 |

0.1.5 需等待 MCP `toolCount > 0` 后再发起测试对话；仅发现服务并不代表工具已注册。
移除后需等列表确认消失，再新增，测试脚本与平台同步流程均遵守该顺序。
控制平面测试 42 项通过、4 项数据库集成跳过；版本选择相关 3 项通过。
浏览器已核对默认值与两个可选项。本次更新的是本地 ARM 环境，未重新导出离线包。
旧 0.1.5 空间仍绑定原镜像，不会自动获得无 Key 修正，需显式升级空间镜像后生效。
