# 观知知识库验证版

本版本在观因企业版控制台提供知识库入口，复用账号、租户、空间和模型提供方。默认关闭；开启后有独立原文 PVC 和独立 Worker，DSH 镜像不变。不是需求说明的完整生产交付。

## 已实现范围

- 个人库、租户内公共库。平台管理员或知识管理员创建公共库；知识管理员可维护本租户公共库，库所有者或获分配的维护者也可管理资料及授权。管理员身份不赋予他人个人库阅读权限。
- 按库授权用户阅读或维护；后端所有列表、检索、原文下载和 MCP 入口都检查权限。
- DOCX、XLSX、文本 PDF、TXT、Markdown 原文按版本保存，10MB 单文件、每库最多 100 篇；PDF 最多 200 页，解析内容最多 18000 字。扫描 PDF 提示需要 OCR。
- Worker 解析、生成带逐字来源引用的 Wiki 草稿；人工编辑和审核后才生成索引并发布。草稿、原文版本和编辑版本用于并发校验。
- 原文更新保留旧发布版本，新任务失败仍可检索旧版；过时任务无法覆盖新版。删除原文立即从检索和读取入口排除其对应 Wiki；逻辑删除保留文件以便后续回收。
- 单空间统一知识 MCP，绑定多个库；参数中库 ID 仅缩小权限范围。工具为 `knowledge_search`、`knowledge_read_source`。
- 个人库由所有者确认空间真实成员范围及平台管理员代入访问能力。成员新增使个人库绑定失效，重新确认才恢复；成员移除不扩大范围。
- 公共库必须授权空间全部未删除成员（含停用成员，保守校验）。撤权后运行时重新计算，某库失效不影响其余有效绑定。
- 空授权返回无可用知识。原文通过每次鉴权的 API 下载，不使用长期裸链接。
- 授权、撤权、绑定、上传、删除、检索、来源读取记录在 `knowledge_audit`；不记录模型密钥、用户查询正文或原文正文。

## 运行与部署

首次部署前必须先在 PostgreSQL 安装 pgvector >=0.8.0 并串行执行知识迁移；参照 [pgvector 升级说明](pgvector-deployment.md) 构建数据库和控制台镜像。主 Dockerfile 已包括知识模块及解析依赖。验证镜像必须分别在目标架构构建；当前本地标签为 `host.docker.internal:5001/guanyin-control-plane:enterprise-knowledge-connections-preview.2`，不得直接当作 AMD64 生产包。

1. 备份数据库，确认 StorageClass 可提供 PVC。应用 `deploy/knowledge/pvc.yaml`。
2. 更新控制面镜像，再应用 `deploy/knowledge/control-plane.patch.yaml` 的战略合并 patch。
3. 等待控制面就绪，它会创建知识表。应用 `deploy/knowledge/worker.yaml`，使用与控制面相同的镜像。
4. Worker 使用控制面的 ServiceAccount 读取模型 Secret，数据库继续从 `guanyin-database` 引用。模型 Secret 名为 `guanyin-model-<provider id>`，数据键为 `apiKey`，不复制到知识配置或前端。
5. 原文 PVC 使用 ReadWriteOnce，Worker 通过节点亲和性与控制面放在同一节点。它不是跨节点高可用方案。生产若需多节点，应先采用已验证的 RWX 或对象存储适配方案。

```sh
kubectl apply -f deploy/knowledge/pvc.yaml
kubectl -n guanyin-enterprise-system patch deployment guanyin-control-plane --type=strategic --patch-file deploy/knowledge/control-plane.patch.yaml
kubectl -n guanyin-enterprise-system rollout status deployment/guanyin-control-plane
kubectl apply -f deploy/knowledge/worker.yaml
```

开关 `KNOWLEDGE_ENABLED=true` 控制页面、API 和受管 MCP 接入。`KNOWLEDGE_WORKER_MODE=external` 禁用控制面内任务执行，由独立 Worker 负责。`KNOWLEDGE_ROOT=/data/knowledge` 必须指向持久卷。未使用独立 Worker 的测试进程可以保留内联模式。

Worker 每次只处理一个任务，数据库锁跳过已领取记录；任务持有租约并续期。进程异常退出后超过十分钟未续期的任务可被重新领取。临时解析在线程中完成，30 秒超时、JS 堆上限 256MiB，Worker 容器内存上限 1GiB。需结合生产真实文件继续做容量测试。

## 模型配置与检索

平台管理员在“知识库 → 模型设置”直接选择模型管理中已登记的整理模型和向量模型。当前只适配 OpenAI Chat Completions 和 embeddings 接口；配置不会回显密钥。可以是同一网关的不同模型，也可以使用不同提供方。新配置保存后由 Worker 读取。

当前采用 PostgreSQL pgvector 类型和 HNSW 索引，数据库内过滤权限并计算相似度，仅返回前 8 条结果。向量 JSON 列作为迁移兼容数据暂时保留，不再由控制台扫描；原 2000 分块限制已移除。1～2000 维使用 vector HNSW，2001～4000 维使用 halfvec HNSW 候选及 float32 重排，更高维仅数据库精确检索。生产部署、迁移和回滚详见 [pgvector 升级说明](pgvector-deployment.md)。更换 embedding 模型、服务版本或维度后应重新处理和发布资料；不可将不同 embedding 空间混用。

知识模型调用由知识 Worker 发出，暂不纳入 DSH 用量统计。模型生成内容必须人工审核，资料属于不可信输入，引用校验不能证明模型结论全部正确。

以下尚未交付：pgvector/全文混合检索、OCR、旧 Office、跨原文融合 Wiki、图谱、逐行 PDF/XLSX 位置引用、可视化版本差异与合并、原文二进制的 DSH 工作副本下载工具、用户组授权、知识所有权转交、文件清理回收、备份恢复自动化及生产质量/压力验收。原文按文档版本追溯，模型 quotes 验证为原文逐字子串；DOCX/XLSX/PDF 的解析文本保留段落/行/页标记。

库所有者被停用或删除时，知识访问暂停；暂不自动转交。共享空间的平台管理员代入能力是当前平台已有边界，授权确认中明确展示。第一版没有实现 DSH 内部访客/分享链接的枚举或管控，因此试用空间须关闭此类入口。新成员可能看见历史回答；撤权只能阻止新的读取，不能收回既有回答、上下文和下载副本。

原文与 Wiki/授权元数据必须联合备份。关闭功能的回退方式是 `KNOWLEDGE_ENABLED=false`、停止 Worker 并保留知识 PVC；不要清空文件或删除数据库知识表。知识任务数据未向 DSH 空间 PVC 写入。

## 资料上传与处理参数更新（2026-11-22）

上传窗口采用用户提供的参考图布局，保留平台样式。支持追加多文件队列、基础格式/大小/空文件校验、逐项移除、清空、总大小、逐项上传与失败重试。单文件仍为 10MiB，每个弹窗最多 20 个文件，库上限 100 篇不变；PDF 文本层、文件真实格式及提取文本长度由后台解析确认，前端不会伪称已完成全文校验。

使用 XMLHttpRequest 的 upload progress 显示真实传输进度，字节发送完毕后先显示“确认保存中”，收到成功响应后才显示原文已入库。后台进度只显示排队、解析、Wiki 整理、待审核、索引和失败的真实阶段，不生成伪百分比。弹窗每三秒查询当前库中本次文件的状态；成功项不会随批量重试重新发送。清空队列不删除已入库文件。登出或切换身份会中止客户端上传并清空文件列表，已在服务端完成的保存不会因此撤销。

每个队列项使用固定 `x-upload-id`，服务端 `knowledge_upload_requests` 记录原文件摘要、目标版本、用户、库及参数指纹。同一标识与相同内容重试返回同一文档版本；并发重试也只保存一次。内容或选项变化却复用旧标识时返回 409。已开始上传的队列锁定参数，重新选择文件或清空队列后可改配置。网络失败的重试可重新传输字节，但不重复创建文档或原文版本；不是断点续传协议。

高级设置保存至原文版本 `processing_options`。新上传默认：标题与段落边界优先切分，目标 1000 字符，重叠 100 字符，过滤控制字符及多余空行，生成摘要关键词。固定长度切分可选；长度 200～2000，重叠不超过长度 25%。这里按 JavaScript 字符长度处理，并避免切开代理对；不是 token 数、嵌入模型语义切分或实体识别。超长段落按长度兜底，Wiki 审核发布时按已保存的选项生成索引。清洗不改二进制原文，保留代码围栏内部空行，逐字引用仍须匹配原解析文本。

已存在版本的空参数按旧规则解释：1600 字符固定切分，无重叠，不清洗，不额外生成摘要，不自动重建已有索引。新摘要最多 500 字，关键词最多 10 个且每个最多 30 字；生成失败或格式不合法进入处理失败，可重试。摘要和关键词可在审核侧栏修订，与 Wiki 共用编辑版本并发校验，已发布版本用于普通阅读者；文档列表可以检索名称、摘要和关键词。普通阅读者及空间 MCP 不能通过猜测版本读取未发布原文，维护者仍能下载当前待审核原文。

上传弹窗 GET 模型状态只检查登记、启用及凭据解析，显示“已配置，连接待检测”。点击“检测模型连接”才实际调用整理与 embeddings 接口，并校验响应结构；状态附本次检测时间，不保证持续可用。探测最多 30 秒，会产生少量模型调用，仍不计入 DSH 用量统计。配置与探测接口仅对本库维护者开放，不回显密钥或模型服务地址。

## Wiki JSON 生成失败排查与修复（2026-11-23）

两篇用户自行上传的 DOCX 在 drafting 阶段失败，旧错误为“模型未返回可校验的 Wiki JSON”。Word 解析阶段已完成。旧代码只保存统一解析错误，没有保存当次模型 finish_reason 和 token 统计，因此无法事后确定原失败是截断还是格式错误。同条件对第二篇手册重新调用一次成功：finish_reason=stop，正文 4107 字符，completion_tokens=4191，其中 reasoning_tokens=1963；这次复测不能作为原失败的具体根因证明。

适配器现在兼容正文前后的空白和完整 JSON 代码围栏，识别空正文、只含推理过程、length 截断及格式错误。JSON 生成问题最多自动重新生成一次，要求更简明且完整的 JSON；初次上限仍不超过 5000 token，重试不超过 10000，并遵守模型管理配置的更低 maxTokens 上限及 maxTokensField。HTTP 失败和内容拒绝不作为格式问题自动重试。绝不把 reasoning_content 代替正式正文，也不修补或执行模型返回的代码。

model_info.draftDiagnostics 保存每次结束原因、请求输出上限、正文/推理长度与数字型 token 统计，不保存模型原始响应、推理正文、原文或密钥。持续失败显示具体类别，草稿、引用、摘要和关键词的原有校验继续有效。默认测试 55 项通过、6 项环境依赖用例跳过，独立 PostgreSQL 集成测试另行通过。

修复后的实际重试进一步复现了截断：两篇手册首次生成均返回 finish_reason=length、completion_tokens=5000、reasoning_tokens=5000、正文长度为 0。自动提高至 10000 后，两篇分别以 7958 和 5654 completion tokens 正常结束，来源引用和摘要关键词校验通过。两篇现均为 review、published_version=null；没有自动发布或重新导入原文件。重试记录使用系统维护标识写入知识审计，既有已发布资料保留。


## 生产可调整预算与失败恢复（2026-11-23）

为避免生产环境依赖修改代码才能调参，平台管理员可在“知识库 → 模型设置 → Wiki 生成与恢复”调整首次整理预算和自动重试预算。新默认分别为 16000 与 32000 token，设置范围 1000～64000，重试值不得小于首次值。模型管理若登记了更低 maxTokens，实际请求仍受该上限约束；没有登记模型上限时，管理员须按真实服务能力设置，不将平台配置范围当作模型能力承诺。

配置保存到 knowledge_settings 并记录审计；Worker 每个任务开始时读取，新的上传和手动重试无需重发镜像或重传原文。运行中的任务继续使用启动时快照。生成预算调整不会改变向量模型，不触发已有索引重建。此配置入口需先随本版本上线，之后日常调参可直接在页面完成。

维护者在文档“查看”侧栏可展开“生成记录与排错”，看到每次请求预算、结束原因、正文字符数及服务返回的 token 统计。截断提示引导调整生成预算并核对模型管理输出上限。鉴权失败、400/422 参数错误、429 限流/额度、5xx 服务故障、连接失败和超时分别给出恢复方向，不暴露服务地址、密钥和原始响应。失败保留原文，新版整理失败不撤销旧发布版本；修正配置后通过现有重试入口恢复。格式生成最多自动重试一次，不做无界重试，也不跳过引用和人工审核要求。

相关单元测试与独立 PostgreSQL 集成测试通过，包含超出旧 10000 固定上限的配置、模型硬上限裁剪、非法和倒置预算拒绝、配置持久化、限流错误提示及界面设置提交的 DOM 模拟。真实浏览器视觉检查尚未完成。此改造提供恢复手段，不保证任意服务或资料始终生成成功。
