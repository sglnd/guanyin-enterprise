# 观因平台 Stitch 设计输入包

> 文档状态：基于当前 `guanyin-platform` 代码整理。标记为“当前”的能力已经实现；标记为“下一阶段”的能力用于 DSH 观因化设计，不应误认为已经完成。

## 1. 可直接提交给 Stitch 的设计任务

请为“观因（Guanyin）智能工作空间平台”设计一套完整、统一、可落地的企业级 Web 产品界面。

观因是内部团队使用的多租户 AI Agent 控制平面，负责管理用户、租户、共享工作空间、空间访问关系、空间生命周期和审计。用户从观因登录并选择工作空间，然后进入基于 DeepSeek Harness Core 的 Agent 工作区。最终产品不应让普通用户感到自己从观因跳转到了另一个产品；控制台与 Agent 工作区必须具有统一的品牌、导航、用户身份展示、颜色、字体、间距、圆角和交互语言。

设计关键词：克制、可信、专业、安静、高效、安全感、东方但不仿古、企业级 AI 工具。避免消费级聊天应用的强渐变、过度发光和大面积卡通插画；避免直接模仿 DeepSeek、ChatGPT 或其他现有 AI 产品。以石墨黑、纸张灰、朱砂红和松石绿为核心色彩，保留观因现有 Logo 的辨识度。

请同时设计桌面端和移动端，重点输出以下页面：

1. 登录页。
2. 普通用户的“我的工作空间”。
3. 平台管理员的“空间管理”。
4. “用户与租户管理”中的成员页。
5. “用户与租户管理”中的租户页。
6. 创建空间页。
7. 空间设置与成员管理抽屉或弹窗。
8. 用户编辑、用户审计、临时密码展示。
9. 进入空间后的观因 Agent 工作区外壳，包括统一顶栏、当前登录人、租户、空间名、空间角色、返回控制台、管理员代入警示。
10. 空间启动中、已休眠、异常、空数据、无权限等状态。

不要改变产品核心信息架构和权限模型，但可以优化页面层级、表格、卡片、操作入口和弹窗形式。普通用户不应看到底层 DSH、Pod、Kubernetes 或镜像架构等技术术语；这些信息只能出现在管理员的高级信息区域。

请输出可实现的设计系统：颜色变量、字体层级、间距、圆角、阴影、按钮、输入框、选择器、标签、表格、卡片、弹窗/抽屉、提示条、空状态、加载骨架和响应式规则。设计结果需要适合转成 CSS variables，并同时应用于观因控制台和 DSH 品牌插件。

## 2. 产品定位

### 产品名称

- 中文：观因
- 英文：Guanyin
- 当前英文辅助语：`GUANYIN AGENT PLATFORM`
- 当前产品主张：让智能能力，安全地服务每一个团队。
- 当前产品特征语：安全隔离 · 版本可控 · 简洁协作

### 产品职责

观因是 DSH 多租户控制平面，不负责构建 DSH Core。观因负责：

- 用户与登录会话。
- 租户管理。
- DSH 工作空间创建和运行状态管理。
- 用户与空间的多对多授权。
- 空间角色与权限。
- 空间启动、停止和空闲休眠。
- 管理员代入访问。
- 操作审计。
- 将已授权用户安全路由到对应 DSH 工作空间。

### 产品边界

- 一个空间对应一个独立 DSH Deployment、Service、Secret 和持久卷。
- 同一个空间可以有多个成员。
- 普通用户只能访问已授权空间。
- 工作空间可以手动停止、唤醒或按空闲策略自动休眠。
- DSH Core 是底层运行核心；普通用户界面应统一称为“观因工作空间”或“Agent 工作空间”。

## 3. 目标用户与权限

### 平台管理员 `platform_admin`

可以：

- 查看所有空间。
- 创建租户、用户和空间。
- 编辑用户显示名称、租户、角色和启用状态。
- 初始化用户密码。
- 配置空间名称、休眠策略和空间成员。
- 启动或停止任意空间。
- 代入访问任意运行中的空间。
- 查看全局审计和单个用户审计。

设计要求：危险或越权操作必须有明确的视觉层级。管理员代入访问不是普通“进入空间”，应显示确认说明，并在工作区持续显示代入状态。

### 租户管理员 `tenant_admin`

当前数据模型已有该角色，但当前控制台只有平台管理员可以进入管理区域。设计时保留角色展示，不擅自新增尚未实现的租户级管理能力。

### 普通用户 `member`

可以：

- 查看自己有权访问的空间。
- 进入运行中的空间。
- 唤醒已休眠空间。
- 负责人或运维者可以停止空间。
- 普通成员不能停止空间。

### 空间角色

- `owner`：负责人。每个空间最多一个负责人，不能直接移除；必须先转移负责人。
- `operator`：运维者。可以进入、唤醒和停止空间。
- `member`：成员。可以进入和唤醒空间，不能停止空间。

## 5. 当前整体布局

### 桌面端

- 应用采用左侧固定导航栏 + 右侧内容区。
- 左侧栏宽度：244px。
- 左侧栏包含 Logo、一级导航和底部登录用户信息。
- 内容区最大宽度：1400px，水平居中。
- 内容区内边距：上下 40px、左右 48px。
- 页面头部左侧为英文 eyebrow 和页面标题，右侧当前显示 DSH 版本。
- 空间使用响应式卡片网格，最小卡片宽度 280px。
- 用户和租户页当前使用左侧创建表单、右侧列表的双栏结构；左列 340px。

### 移动端

- 800px 以下，左侧栏变为顶部横向导航。
- 隐藏侧栏品牌文字和用户区。
- 内容区内边距变为 28px / 18px。
- 双栏表单与列表改为单栏。
- 700px 以下，空间设置和成员管理表单改为单列。
- 1000px 以下，用户表格改为两列流式布局并隐藏表头。

设计优化目标：移动端不能仅仅是把桌面元素堆叠；需要给导航、用户身份、表格操作和弹窗设计明确的移动交互。

## 6. 页面详细需求

### 6.1 登录页

当前布局：左右分屏。

左侧品牌区：

- 深色渐变背景。
- 观因 Logo 和名称。
- `GUANYIN AGENT PLATFORM`。
- 主标题“让智能能力，安全地服务每一个团队。”
- 说明“统一管理身份、租户与独立 DSH 工作空间。”
- 底部“安全隔离 · 版本可控 · 简洁协作”。

右侧登录区：

- 欢迎回来。
- 登录工作空间。
- 用户名。
- 密码。
- 登录按钮。
- 行内错误信息。

状态：默认、输入聚焦、提交中、用户名或密码错误。移动端隐藏左侧品牌区，但仍需保留简洁的移动品牌头。

### 6.2 我的工作空间

页面目标：让用户快速判断“我有哪些空间、空间能否进入、我在空间中的角色、是否会休眠”。

页面元素：

- 页面标题“我的工作空间”。
- 区块标题“已授权空间”。
- 刷新状态。
- 空间卡片网格。
- 无授权空间的空状态。

空间卡片字段：

- 空间名称。
- 所属租户。
- 当前用户空间角色。
- 运行状态。
- 休眠策略。
- 工作空间核心版本；普通用户未来应弱化或隐藏。
- 创建日期。

卡片操作：

- 运行中：进入工作空间。
- 已休眠：启动空间。
- 创建中/启动中/休眠中：按钮禁用并自动轮询。
- 异常：重试启动，清楚显示异常状态。
- 负责人/运维者：停止空间。

空间状态：

| 状态 | 中文 | 设计语义 |
| --- | --- | --- |
| `running` | 运行中 | 成功/可进入 |
| `starting` | 启动中 | 处理中，约束重复操作 |
| `provisioning` | 创建中 | 处理中，显示初始化进度感 |
| `stopped` | 已休眠 | 中性，提示数据仍保留 |
| `stopping` | 休眠中 | 处理中 |
| `error` | 异常 | 错误，提供恢复操作 |

### 6.3 空间管理

仅平台管理员可见。

页面包含：

- 所有空间卡片。
- 每个空间的成员数量。
- 管理员代入访问。
- 启动/停止空间。
- 管理空间。
- 全局管理员审计日志及分页。

管理员代入访问需要明确表达：

- 管理员即将进入共享空间。
- 操作会写入审计日志。
- 这是代入访问，不是在模拟某个具体成员。
- 进入 DSH 后应持续显示警示条。

当前采用浏览器原生确认框，设计稿应改为品牌化确认弹窗。

### 6.4 用户与租户：成员

当前使用页签切换“成员 / 租户 / 创建空间”。成员页为创建表单 + 用户列表。

创建用户字段：

- 显示名称。
- 用户名。
- 初始密码，至少 8 位。
- 所属租户。
- 平台角色：普通用户或租户管理员。

用户列表字段：

- 显示名称。
- 用户名。
- 是否已停用。
- 所属租户。
- 平台角色。
- 操作：审计、编辑、初始化密码。

平台管理员账号不能在当前页面编辑或初始化密码。

### 6.5 用户编辑

当前为模态弹窗。

字段：

- 显示名称。
- 所属租户。
- 平台角色。
- 是否允许登录。

设计时需要明确“停用用户”与删除用户不同；停用后不能登录，但历史审计仍保留。

### 6.6 初始化密码

流程：

1. 用户列表点击“初始化密码”。
2. 显示确认提示；说明用户现有登录会话会立即失效。
3. 服务端生成临时密码。
4. 临时密码只展示一次。
5. 可复制，完成后关闭。

设计要求：一次性敏感信息需要醒目但不惊慌；复制成功要有明确反馈；不要把密码写进日志或普通通知。

### 6.7 用户审计

当前为宽模态弹窗，分页每页 20 条。

展示：

- 用户名称和用户名。
- 操作名称。
- 操作时间。
- 标准化操作说明。
- 操作人。
- 来源 IP。
- 页码和总条数。

隐私要求：仅记录元数据，不记录对话正文、密码、密钥或请求内容。

### 6.8 用户与租户：租户

创建租户字段：

- 租户名称。
- 租户编码，例如 `risk-team`。

租户列表字段：

- 租户名称。
- 租户编码。
- 成员数量。

当前没有租户编辑和删除，不应在设计稿中默认增加可用按钮。

### 6.9 创建空间

当前为单列卡片表单，最大宽度 520px。

字段：

- 空间名称。
- 所属租户。
- 休眠规则。
- DSH 版本，当前只读。

休眠选项：

- 永不休眠。
- 空闲 30 分钟。
- 空闲 1 小时，当前默认。
- 空闲 2 小时。
- 空闲 4 小时。
- 空闲 8 小时。

操作：“创建并启动”。创建后再到空间管理绑定成员。

后续版本会支持多个观因 DSH 镜像版本，因此设计中可以为版本选择预留位置，但当前必须表现为只读或唯一选项。

### 6.10 空间设置与成员管理

当前为宽模态弹窗。

空间设置：

- 空间名称。
- 休眠规则。
- 保存状态和成功提示。

成员管理：

- 只能选择同一租户的用户。
- 选择空间角色：成员、运维者、负责人。
- 已绑定用户再次提交时更新角色。
- 负责人不能直接移除。
- 展示用户显示名称、用户名、空间角色和移除操作。

设计建议：此内容信息量较大，可以使用右侧抽屉或独立详情页，但必须保持上下文清楚，避免把空间设置和成员权限混在一个紧凑表格中。

### 6.11 管理员审计日志

位于空间管理页面空间卡片下方。

字段：

- 时间。
- 操作人和操作类型。
- 目标空间和目标用户。
- 分页。

主要审计事件：登录、退出、创建/编辑用户、初始化密码、进入 DSH、DSH 操作、启动/停止空间、创建/修改空间、设置/移除空间成员、管理员代入访问。

### 6.12 观因 Agent 工作区（下一阶段）

这是当前 DSH 页面完成白标后的目标形态。

必须新增或统一：

- 使用观因 Logo、颜色和产品名称。
- 普通用户看不到 `DeepSeek Harness` 或 `DSH` 品牌字样。
- 显示当前用户姓名、用户名、租户、空间名称和空间角色。
- 提供清晰的“返回控制台”。
- 保留 Agent 对话、会话、文件、工具、Skill、MCP 等核心功能布局。
- 管理员代入时顶部持续显示不可忽略的警示条。
- 普通用户不显示底层核心版本；管理员可在“关于/运行信息”查看。
- 控制台和工作区之间切换时，不能产生跳入第三方产品的视觉割裂。

身份示例：

```text
张三
风控团队 · 风险分析空间 · 运维者
```

管理员代入示例：

```text
平台管理员正在代入访问“风险分析空间”
本次访问将被审计
```

## 7. 当前视觉基线

### 色彩

当前 CSS 变量：

```css
--ink: #17201e;
--muted: #68736f;
--line: #e4e8e6;
--paper: #f6f7f5;
--white: #ffffff;
--accent: #b9382f;
--accent-dark: #8f2923;
--green: #2d8067;
--nav: #141a19;
```

设计语言解释：

- `ink/nav`：石墨黑与深绿黑，用于导航和主要文字。
- `paper`：偏暖纸张灰，用于页面背景。
- `accent`：朱砂红，用于品牌和关键操作。
- `green`：松石绿，用于成功和运行状态。
- 黄色/棕色用于处理中和休眠策略。

Stitch 可以优化色值和对比度，但应保持上述品牌气质，并满足 WCAG AA 文本对比度。

### 字体

当前字体栈：

```css
Inter, "PingFang SC", "Microsoft YaHei", sans-serif
```

需要定义完整层级：产品大标题、页面标题、区块标题、卡片标题、正文、辅助文字、标签、表格和代码/临时密码。

### 圆角与阴影

- 输入框/按钮：9px。
- 卡片：14px。
- 弹窗：16px。
- 当前卡片阴影较轻：`0 8px 30px #18231f08`。
- 弹窗使用较强背景遮罩和阴影。

### Logo 资产

当前正式使用：

```text
assets/branding/guanyin-mark-graphite-cinnabar-v4.png
```

备选资产：

```text
assets/branding/guanyin-mark-512.png
assets/branding/guanyin-mark-contrast-v3.png
assets/branding/guanyin-mark-minimal-v2.png
assets/branding/guanyin-mark-source.png
```

Logo 不应被重新绘制成观音人物或宗教符号；“观因”表达的是观察原因、洞察因果。

- Modal / Drawer / Confirmation Dialog。

## 9. 关键用户流程

### 普通用户进入空间

```text
登录
→ 查看已授权空间
→ 空间运行中：直接进入
→ 空间已休眠：启动
→ 启动中自动刷新状态
→ 就绪后进入观因 Agent 工作区
```

### 负责人或运维者停止空间

```text
我的工作空间
→ 选择运行中的空间
→ 停止空间
→ 状态变为休眠中
→ 最终显示已休眠，持久数据仍保留
```

### 管理员创建和授权空间

```text
创建租户（如需要）
→ 创建用户（如需要）
→ 创建空间并启动
→ 空间管理
→ 配置休眠策略
→ 添加成员并设置角色
→ 成员在“我的工作空间”看到该空间
```

### 管理员代入访问

```text
空间管理
→ 选择运行中的空间
```

## 10. 交互与内容原则

- 使用中文为主，英文只作为品牌辅助和技术管理信息。
- 面向普通用户使用“工作空间”，避免使用 Pod、Deployment、镜像、DSH RPC 等术语。
- 关键动作必须说明结果，例如停止空间不会删除持久数据。
- 异步启动不能让用户误以为操作失败，应显示持续状态和下一步预期。
- 危险操作使用语义明确的确认，不依赖颜色作为唯一提示。
- 加载、成功、错误、空数据、禁用和权限不足都要有设计状态。
- 表单校验应靠近字段展示，避免只使用浏览器 `alert()`。
- 审计界面强调可追溯性，但不展示敏感正文。
- 普通用户的核心任务是进入空间；管理操作不能抢占主要视觉注意力。
