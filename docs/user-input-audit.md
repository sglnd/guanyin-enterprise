# 用户聊天输入审计

## 当前审计范围

根据 2026-10-27 的简化要求及删除操作补充要求，`createAuditLog` 仅允许 `user_login`、
`user_chat_input`、`session_delete` 写入；查询与分页计数也只包含这三类。
DSH 转发入口不再按 POST 请求追加通用 `dsh_operation` 日志。
退出、进入空间、查看、刷新、空间与配置管理等其他事件不再写入审计。
历史杂项记录不物理删除，继续按原有一年到期规则清理，但不再出现在列表中。
单测 51 项通过、4 项数据库集成默认跳过；审计与删除模块另外在隔离数据库事务中
7 项测试全部通过，包括杂项不计入筛选与分页、历史记录保留以及正文持久化。

### 删除会话

仅拦截经过平台的 `POST /__guanyin/sessions/delete`；prepare、查看菜单、取消不记。
提交删除前保存操作者、空间、会话 ID、时间和 `submitted` 状态，不保存确认凭据或会话正文。
首次写入失败不转发删除请求；之后根据删除接口的响应更新同一条审计，200 为成功，
4xx 为请求失败，5xx 或连接异常标为结果未确认。若结果回写失败，初始提交记录仍保留，
不会错误地标为成功。空间侧原有确认凭据、活动会话和依赖检查继续执行。
本次仅更新平台，无需更新空间镜像；直接绕过平台操作文件或调用空间接口不在覆盖范围内。
新增 4 项测试覆盖提交/结果、确认凭据排除、审计失败拦截和结果写入中断。

2026-10-27：平台转发入口新增 `user_chat_input` 审计。无需更新 DSH 镜像。

## 范围

- 覆盖经过观因平台的 `POST /api/session/prompt`，兼容 0.1.5 与 0.2.1 的
  `payload.args.request` / `payload.args` 两种请求形状。
- 仅提取本次 `request.content` 内 `type=text` 的文字，原样保存到 `details.texts`。
- 关联登录用户、空间、租户 ID、会话 ID、请求 ID、时间、管理员代入标记。
- 不提取上下文、AI 回复、执行结果、图片、附件正文或请求头。
- 这是提交记录，不表示 AI 已完成处理；客户端重复提交会分别记录，并可通过请求 ID 关联。
- 不补录历史；自建客户端绕过平台、直接访问 DSH，以及 API/计划任务内部入口不在本次范围。

## 持久化和展示

读取不超过 16 MiB 的 JSON 请求，校验后直接等待 `store.createAuditLog` 写入完成，
再将原始请求字节转发到空间。不使用吞掉写入错误的通用 `audit()` 包装。
数据库失败返回 503 并提示消息尚未发送；格式错误和超限请求不转发。
只调整聊天请求的 Content-Length，其他 RPC、上传和响应继续按原流程传输。

记录保存在平台 PostgreSQL `audit_logs`，沿用一年查询范围和定期清理，
不依赖空间日志或会话目录。审计查询 API 沿用平台管理员授权。
空间会话删除不会调用平台审计删除。审计没有新增前台删除接口。

审计列表和用户审计弹窗均有“查看用户输入”，显示会话/请求 ID 和完整文字。
正文通过现有 HTML 转义函数显示，长文本可滚动且保留空格、换行。
空间名和用户显示名另存快照，以便关联名称不可用时显示。
