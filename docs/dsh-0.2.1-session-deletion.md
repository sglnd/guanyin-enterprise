# 观因 rc3 会话删除适配

适用镜像：`0.2.1-rc.3-gy.ent.6`。不修改 0.1.5 镜像，不变更共享附件格式。

## 界面与范围

会话行的操作菜单新增红色“删除会话”，归档入口保留。弹窗展示会话名称与清理范围，检查服务端状态后，用户须勾选确认才能点击“确认删除”。取消不会归档、删除或修改会话。

删除仅清理所选会话的独立 JSONL 目录、工作区成员记录、归档/置顶索引和运行时目录索引，并发布原生列表移除事件。工作目录内的文件、共享内容寻址附件、平台审计及用量历史均保留。

运行/自动化任务、子智能体会话，以及仍被分支或子智能体引用的主会话拒绝删除；界面给出原因。暂不做级联删除或共享附件垃圾回收，避免误删关联内容。

高级设置的分类使用中文功能名称，配置区域隐藏项目介绍和外链；表单仍使用原生设置协议。

## 边界与恢复

- 浏览器只调用 `POST /__guanyin/sessions/prepare` 与 `/delete`。观因代理验证空间签名身份、同源请求与动作请求头；原生处理器另外验证每空间内部令牌。
- 准备操作签发绑定用户和会话、有效期两分钟、一次性的确认凭据。确认后再次检查活动及关联状态。
- 先通过原生归档拦截新回合，再释放 AgentFactory 返回的完整 `AgentHandle.dispose`。不能只释放 Agent 注册作用域，否则持久化写入锁仍然存在。
- 领取 JSONL 后端写入声明及内核写锁。仅允许后端解析出的规范会话目录，不接受客户端文件路径。
- 通过同一数据卷内的原子目录移动提交删除；事务记录位于 `DSH_HOME/guanyin-session-deletions/<sessionId>/record.json`，目录和记录均同步落盘。提交前出错恢复原归档/置顶状态；提交后中断保留记录并拦截该会话，重启时完成索引清理和物理清理。
- 注册 `session/created` 与 `agent/pre-step` 拦截，防止删除期间重新创建同一会话或派生依赖。

## 上游升级检查点

实现集中在企业插件 `lib/sessions.js` 和 `web-proxy.mjs`，未修改上游包源码。会话菜单使用 `sidebar.workspaces.session.menu.item`，弹窗使用 `shell.overlay` 与原生 Modal/MenuItemButton。

由于 rc3 没有原生删除 API，后端适配涉及 JSONL 的 `findLog`、`tracker.claimWrite/releaseClaim`、`acquireLease`、`coldLogMemo` 及工作区的目录缓存。AgentFactory 的 `createAgent/resume` 包装仅保留其公开返回句柄；卸载时还原方法。升级必须重新验证这些边界，不能假定跨版本兼容。

## 验证

- 8 项删除/恢复单元测试：清理范围、确认凭据、活动与依赖阻止、确认后状态变化、提交前失败、提交后恢复、符号链接越界及完整生命周期句柄。
- 隔离容器集成：普通会话与已归档会话真实删除，原生列表及工作区成员索引更新，未确认/重放/未认证/跨站及无效 Origin 请求拒绝。
- 直接检查日志目录已物理移除；重启后两条已删除记录仍缺失，未删除记录仍在。
- 模拟模型的浏览器工具、无 Key 请求及用户用量上报回归通过。使用合成数据，没有删除真实空间会话。
- 浏览器检查删除弹窗、勾选门槛、取消保留与各中文配置页；浏览器未执行真实数据的最终删除。

隔离验证命令参见 README 中的 fixture 启动方式；新增 `session-deletion-check.mjs` 仅允许对本地可丢弃测试容器运行。

另外清理所选会话的持久化投影检查点与准备态内存缓存，并在删除期间及本进程后续生命周期中阻止该身份的旧缓存写回。派生全文搜索沿用原生查询器对当前日志集合的校准。升级检查点包括 `sessionProjectionCache.table/put` 和查询器的准备态缓存。

最终镜像额外验证：两条删除会话的独立日志目录及 `storages/session_projcache/sessions/<id>.json` 均不存在；同空间保留会话仍可列出。浏览器截图：`dist/dsh021-validation/rc3-ent6-delete-dialog.png`、`rc3-ent6-config-pages.png`。

本地 K8s 已将既有 0.2.1 测试空间更新到 ent.6，Pod 1/1 就绪；0.1.5 默认镜像保留。真实空间浏览器已确认高级设置中文分类正常。测试容器与 fixture 进程均已停止；真实空间未执行删除操作。
